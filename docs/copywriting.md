# 簡報文案規範

生成或審查簡報內容時，請對照此文件確認文案是否符合規範。

---

## 語言

- 繁體中文撰寫
- 中英文之間保留一個空格（如：「用 Claude Code 開發」）
- 英文技術詞彙不翻譯，保留原文（GitHub、token、DESIGN.md、commit、push）

---

## 標題（h2）

- 15 字以內
- 句尾不加「。」
- 常用句型：問句、對比句（A 才能 B、A 而非 B、A ＋ B，缺一不可）
- 節奏停頓用「，」，不用「——」

**範例**

| ✅ | ❌ |
|---|---|
| AI 做 UI 時，設計規則在哪？ | AI 在做 UI 的時候——設計規則究竟放在哪裡呢？ |
| Token 值 ＋ 使用規則，缺一不可 | Token 值和使用規則都非常重要，不能缺少任何一個 |
| 設計脈絡在，AI 輸出才穩定 | 只有設計脈絡存在，AI 才能夠穩定地輸出結果 |

---

## 說明文字（body）

- 一段最多 2 句
- 每句不超過 30 字
- 並列三項以上時用「、」，不用「，」
- 句尾加「。」

---

## 清單項目（bullet）

- 使用「→」作為項目符號
- 每條一句話，不加句號
- 以動詞或名詞短語開頭，不以「可以」「能夠」開頭

**範例**

```
→ 純文字、Git 版控、任何 AI agent 都能讀
→ 不依賴特定工具，不需要 Figma plugin 或 build pipeline
→ 設計師寫，開發者和 AI 都受益
```

---

## 卡片標題

- 名詞短語為主，8 字以內
- 不加句號

---

## Eyebrow 標籤

格式：`0X / 主題名稱`（英文大寫、monospace）

```
01 / 為什麼
02 / Google DESIGN.md
03 / 格式
```

---

## 技術詞彙大小寫

| 正確 | 錯誤 |
|---|---|
| GitHub | github、Github |
| Claude Code | claude code、ClaudeCode |
| DESIGN.md | design.md、Design.md |
| VS Code | VSCode、vscode |

---

## 禁用寫法

| 禁用 | 改用 |
|---|---|
| ——（破折號） | 句號、分號，或拆成兩句 |
| ...（省略號） | 句號結尾，或直接省略 |
| 非常、十分、極為 | 直接描述，不加程度副詞 |
| 可以讓...、能夠讓... | 直接說結果（→ AI 才能穩定輸出） |
| 三步驟、四個 | 3 步驟、4 個（數字用阿拉伯數字） |
